 5. Cron Jobs

Scheduled tasks are especially interesting when root executes scripts that can be modified by a lower-privileged user.

Observe Processes with pspy

pspy can reveal scheduled jobs and short-lived processes that are not obvious from static cron files. Verify the binary source and inspect permissions before treating an observed task as a privilege-escalation path.

Look for

  • Root-owned cron jobs.
  • Writable scripts executed by root.
  • Relative paths.
  • PATH hijacking opportunities.
 6. Writable Files & Permissions

Not every writable file is useful. Prioritize files that influence authentication, execution or privileged services.

High-Value Targets

  1. /etc/sudoers
  2. /etc/passwd
  3. /etc/shadow
  4. /etc/crontab
  5. /etc/cron.*
  6. Systemd service files.
  7. Application configuration files.
 Writable File Escalation Priority

Prioritize writable files that influence authentication, scheduled execution or privileged services. A writable file is only useful when it is trusted or executed by a more privileged context.

Windows Privilege Escalation

Windows privilege escalation enumeration, exploitation and OSCP methodology.

1. Identity & Token Enumeration

Always start by identifying the current user, groups, privileges and integrity level.

Important privileges:

  • SeBackupPrivilege → Dump SAM / SYSTEM.
  • SeRestorePrivilege → Overwrite protected files.
  • SeImpersonatePrivilege → Token impersonation.
  • High Integrity → Elevated token.
 2. Users & Groups

Enumerate local and domain users and identify privileged group membership.

 3. System Enumeration

Drivers:

 Registry and UAC Checks

Review UAC-related policy values and system context as indicators; do not treat a registry value by itself as proof of an exploitable path.

 Event Log Review

Security event availability depends on audit policy and access rights. Process-creation events can help reconstruct privileged execution and identify useful context.

 Startup and Process Enumeration

Inspect startup entries and relevant services or processes for unusual paths, accounts and writable locations.

 4. Network Enumeration 5. Credential Hunting File Searching Registry Credentials Saved Credentials PowerShell History Credential Reuse Validation

When authorized credentials are discovered, verify account scope and effective privileges before attempting any alternate-account access. Do not create or trigger tasks or remote sessions without explicit authorization.

 Additional Credential Artifacts

Check the native PowerShell history path and other authorized credential artifacts. Treat output as sensitive and avoid exposing secrets in logs.

 6. Interesting Files Enumeration

Search for configuration files, scripts, backups and documents that may contain credentials, connection strings, tokens or other useful information.

File and Directory ACL Review

Check ownership and ACLs on files referenced by privileged services or tasks. A weak ACL is actionable only when it grants the current account the required write access and a privileged execution trigger exists.

 7. Services Enumeration

Look for:

  • Unquoted service paths.
  • Writable service binaries.
  • Weak service configuration permissions.
  • Services running as SYSTEM.

Service Permissions

Inspect the service descriptor and file ACLs; verify all escalation conditions.

 8. Unquoted Service Paths

An unquoted service path containing spaces may allow Windows to execute an unexpected binary if an intermediate directory is writable.

All conditions must be true:

  • The path contains spaces.
  • The executable path is not quoted.
  • An intermediate directory is writable.
  • The service can be triggered.

Important: An unquoted path alone does not make a service exploitable.

9. Service Binary Hijacking

If a service runs as SYSTEM and its executable is writable, replacing the binary can result in SYSTEM code execution.

Exploitation conditions:

  • Service runs as LocalSystem.
  • Binary is writable.
  • The service can be restarted or triggered.

 10. DLL Hijacking

Look for applications or services loading DLLs from writable directories.

11. Scheduled Tasks Enumeration Task Filtering Inspect Task Referenced Files Permissions Scheduled Task Context Review

For custom tasks, review the author, principal, triggers, action arguments and referenced working directory. Pay particular attention to scripts or binaries in writable locations.

 12. AlwaysInstallElevated

This is only misconfigured when both the current-user and machine policy values are enabled. Treat MSI installation as a system-level change; use only the designated lab package.

13. SeImpersonatePrivilege Abuse

Check whether the current account possesses SeImpersonatePrivilege.

If the privilege is enabled, token impersonation techniques may allow escalation to SYSTEM depending on the Windows version and execution context.
